# trace branch mixer: first implementation

## status

the theory-led reference runtime is implemented in:

```text
trace_branch_mixer/
```

it is intentionally isolated from the production gui and the legacy soma
controller paths. its purpose is to establish one readable, testable
definition before interface work or performance specialization.

## file map

```text
trace_branch_mixer/core.py
  exact temporal lattice
  authoritative float64 trace state
  affine projected prefix scan
  shared log-scale encoder
  serial swiglu trunk
  tied branch-energy readout

trace_branch_mixer/runtime.py
  immutable tokenizer contract
  optimizer and atomic trace commit
  generation cache
  checkpoint save, validation, and resume

trace_branch_mixer/train.py
  contiguous text streaming
  small and local reference profiles
  reports, dreams, autosave, and resume

tests/test_trace_branch_mixer.py
  mathematical and runtime contract
```

## implemented invariants

- the complete trace state is stored as cpu float64 `[vocabulary, bands]`;
- exact batch advancement equals token-by-token advancement;
- every normalized trace column preserves unit mass;
- rates use exact double-precision phi;
- adjacent rates obey the phi contraction identity;
- the projected batch is generated by an affine parallel prefix scan;
- each projected position equals applying the current embedding to the
  corresponding full trace state;
- the target at a position cannot influence its own prediction;
- the trace state is outside autograd;
- one language loss reaches symbol geometry, scale mixing, and serial depth;
- zero learned branch energy recovers the measured symbol prior;
- training and generation use the same trace transition;
- generated events enter the trace without altering the learned source prior;
- checkpoints validate tokenizer, lattice, direct-channel convention, and
  every learned shape;
- resumed checkpoints reproduce the exact next prediction.

## production continuation

the first implementation did not yet:

- translate legacy checkpoints;
- fuse the projected scan into a metal or cuda kernel;
- compile the scale blocks or serial trunk;
- preserve a partially consumed tokenizer chunk inside a checkpoint;
- claim a final local throughput or convergence result.

v13.1 now powers the app and adds a translated signed residual bank, io2
learning-rate control, and exact-trace prediction decimation. these mechanisms
leave the trace equations, model tensors, and language objective unchanged.
v13 checkpoints therefore remain shape-compatible, while pre-controller v13
checkpoints begin with a cold residual bank.

remaining work should follow this order:

1. run a longer held-out learning comparison;
2. profile the projected scan, scale encoder, and trunk separately;
3. fuse the projected scan;
4. preserve exact streaming-corpus iterator state;
5. test long-duration controller behavior on held-out language.

the architecture is now a concrete falsifiable object. further mechanisms can
be compared against it rather than quietly becoming part of its definition.
